# finetuning-example-glm5-3

Fine-tune GLM-5.3 (744B parameters) on private data inside a [Tinfoil Container](https://docs.tinfoil.sh/containers/overview)
that holds a whole 8-GPU node, from a Jupyter notebook. The base model is the verified checkpoint Tinfoil serves,
the dataset and the resulting LoRA adapter live on a 16 TB encrypted disk that survives restarts, and the enclave
has no network egress.

```
laptop                                  enclave (8 GPUs, no egress)
  tinfoil container connect ─────────▶  JupyterLab  ──▶  /tinfoil/mpk/…   verified GLM-5.3 NVFP4 pack (read-only, 465 GB)
  browser: upload data, run cells ──▶              ──▶  /workspace        16 TB encrypted volume: data, adapters
                                                          ▲ unlocked at boot with WORKSPACE_KEY (Tinfoil Secret)
```

The notebook streams the checkpoint into transformers with the decoder layers split across the eight GPUs, keeps the
routed experts packed in FP4 and dequantizes them on the fly (`glm_nvfp4.py`), trains a LoRA adapter on a sample
"internal helpdesk" dataset, saves it to the encrypted workspace, and shows the model before and after. Swap in your
own JSONL and it is your data.

This is the full-node version of [finetuning-example](https://github.com/tinfoilsh/finetuning-example), which does the
same on one GPU with Gemma 4 E2B.

## Deploy it

You need the [`tinfoil` CLI](https://docs.tinfoil.sh/containers/cli) logged in to an organization with
Tinfoil Containers and an 8-GPU host (`tinfoil container hosts`).

1. **Fork this repo** (it must stay public: the release measurement is published from it). Or
   deploy `tinfoilsh/finetuning-example-glm5-3` directly and skip the release step.

2. **Create the two secrets.** The notebook login token, and the key that unlocks the workspace.
   The key is 64 random bytes; it is only ever released into an enclave running this measured config.

   ```sh
   openssl rand -hex 32 | tr -d '\n' | tinfoil secret create JUPYTER_TOKEN --value-file -
   openssl rand -base64 64 | tr -d '\n' | tinfoil secret create WORKSPACE_KEY --value-file -
   ```

3. **Stage the base model on your host.** This downloads the weights once, wraps them into a
   verified pack and prints the `models:` block, which already matches `tinfoil-config.yml`.

   ```sh
   tinfoil model wrap Inferact/GLM-5.3-NVFP4 --commit ce67b36f3669192b5bb233819f0fda6c8a9837f8 \
     --host control.<host>.tinfoil.sh --wait
   ```

4. **Release** (forks only): `gh workflow run tinfoil-release.yml -f version=v0.1.0`. The workflow
   builds the image, pins its digest into `tinfoil-config.yml`, tags the release and publishes the
   enclave measurement.

5. **Deploy.**

   ```sh
   tinfoil container create finetune-glm --repo <owner>/finetuning-example-glm5-3 --tag v0.1.0 \
     --host control.<host>.tinfoil.sh --secret JUPYTER_TOKEN --secret WORKSPACE_KEY
   ```

   Ready takes a few minutes (image pull, boot, and formatting the volume on first start).
   `tinfoil container get finetune-glm` shows the status.

6. **Open the notebook through a verified tunnel.** The proxy checks the enclave's attestation
   against the published measurement before forwarding anything.

   ```sh
   tinfoil container connect finetune-glm -p 8888
   # then open http://127.0.0.1:8888/?token=<JUPYTER_TOKEN>
   ```

   Run the cells top to bottom. `notebook/finetune.ipynb` is the same file, if you want to read it first.

## What is where

| Path | What |
|---|---|
| `tinfoil-config.yml` | The measured deployment: 8 GPUs, model pack, encrypted `workspace` volume with `key-secret`, the notebook container, no `networks:` |
| `Dockerfile`, `entrypoint.sh` | PyTorch + transformers + PEFT + JupyterLab; seeds the workspace on first start |
| `glm_nvfp4.py` | Loads the NVFP4 checkpoint across the GPUs; experts stay packed and are dequantized inside each forward pass |
| `notebook/finetune.ipynb` | The tutorial notebook (generated by `notebook/build_notebook.py`) |
| `data/train.jsonl`, `data/eval.jsonl` | Sample private dataset (generated by `data/make_dataset.py`) |

## Bring your own data

Training data is JSONL, one conversation per line:

```json
{"messages": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]}
```

Drag the file into `data/` in the JupyterLab file browser and change the path in section 2. Uploads go
over the attested connection straight onto the encrypted volume.

## Persistence and updates

The `workspace` volume is a dm-crypt + dm-integrity disk keyed by `WORKSPACE_KEY`. Its size is a host setting
(16 TB on the host this example runs on; ext4 caps a single image file just under 16 TiB). Stopping, starting or updating the container keeps it; deleting the
container deletes it. Section 8 of the notebook reloads the saved adapter after a restart.

To keep the key out of Tinfoil's hands entirely, release both secrets from your own
[keyserver](https://docs.tinfoil.sh/containers/private-secrets) by setting `keyserver-url` in the config.
